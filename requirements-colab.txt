# --- What DPOConfig changes out from under you ------------------------------
# Read out of trl 0.29.1's source, not recalled. DPOConfig inherits from
# TrainingArguments via trl's BaseConfig, and BOTH layers move defaults.
# Notebook 03 sets every one of these explicitly; if you adapt it, keep doing so.
#
# Changed by trl (BaseConfig):
#   gradient_checkpointing      -> True   (with PEFT this needs
#                                          enable_input_require_grads(), or the
#                                          first backward dies)
#   bf16                        -> None, resolved to `not fp16` in __post_init__
#                                          (so it switches ITSELF on, and a
#                                          Turing T4 then emulates it, slowly)
#   logging_steps               -> 10
#
# Changed by trl (DPOConfig):
#   learning_rate               -> 1e-6   (a full-fine-tune rate, far too low for
#                                          LoRA's ~0.9% of the weights)
#   loss_type                   -> ["sigmoid"], a LIST since trl 0.29. Passing
#                                          the bare string is not the same thing.
#   max_length                  -> 1024, with truncation_mode="keep_start", so
#                                          overflow eats the completion — the
#                                          only part DPO scores
#   beta                        -> 0.1
#
# Inherited unchanged from TrainingArguments, and still worth setting, because
# the defaults suit a different job:
#   per_device_train_batch_size -> 8      (one DPO example is TWO sequences, and
#                                          the reference forward doubles it again)
#   lr_scheduler_type           -> "linear"
#   save_strategy               -> "steps", every 500
#
# Note also that trl's preference collator passes `padding_side` explicitly on
# every call (left for prompts, right for completions), so it neither needs nor
# reads the padding side of the tokenizer you hand it as `processing_class`.
# Notebook 03 still left-pads, for its own batched generation.

# --- What vllm changes out from under you, notebook 05 only -----------------
# Read out of vllm 0.19.1's package metadata, not recalled.
#
#   torch                   HARD PINNED to one exact version. vllm ships
#                           precompiled CUDA kernels linked against a single
#                           torch ABI, so installing it REPLACES Colab's build.
#                           Budget several minutes and a runtime restart. This
#                           is the opposite of the rule notebooks 01-03 follow,
#                           and the reason is that there is no choice.
#   transformers            specifier excludes 5.0 through 5.5.0 and allows
#                           everything after, so the 5.15.0 above is fine and
#                           nothing gets downgraded. Re-check this whenever
#                           either pin moves — most vllm/transformers pairs in
#                           2026 did conflict.
#   torchao                 NOT a vllm dependency, so the uninstall below stays
#                           safe in notebook 05 too.
#   aiohttp, openai         both arrive with vllm, so notebook 05's async load
#                           generator and its OpenAI-client demo need no extra
#                           install.
#
# Hardware: vllm's fast attention backends (FlashAttention, FlashInfer) require
# compute capability 8.0+. On a Turing T4 it falls back to TRITON_ATTN, which
# works but is not what anyone means by "vLLM throughput". Notebook 05 asserts
# sm_80+ rather than quietly producing fallback numbers.
#
# Two config fields decide whether the server starts at all, and neither is a
# training concern — notebook 05 section 4 covers both:
#
#   max_model_len           defaults to the checkpoint's max_position_embeddings,
#                           which for Llama 3.2 is 131,072. At 32 KiB of KV cache
#                           per token that is 4.3 GB for ONE sequence, and the
#                           server exits during startup. Pass --max-model-len.
#   gpu_memory_utilization  is a fraction of TOTAL VRAM, not of free VRAM. Leave
#                           a model loaded in the same process and vllm still
#                           takes its share, silently shrinking the KV cache.
